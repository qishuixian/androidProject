# Day79 · 综合发布与回滚

入口：首页 → Day79 · 综合发布。
源码：[ReleaseChecklistDemo.kt](../app/src/main/java/com/example/myapplication/day79/ReleaseChecklistDemo.kt)。

## 发布不是点击一次按钮

一次可追踪的 Android 发布通常包含：

```text
自动检查 → 构建候选产物 → 真机回归 → 发布记录 → 分批发布 → 监控 → 必要时回滚
```

自动检查可以覆盖编译、Lint、单元测试、变体和 APK/AAB 产物；真机回归要覆盖启动、登录、核心业务、权限、网络异常、返回键和升级数据。每次发布都要记录提交版本、构建任务、`applicationId`、`versionCode`、签名、产物校验值、测试设备和负责人。

## 回滚的前提

回滚不是简单地把旧 APK 覆盖安装。要先确认旧版本仍使用兼容签名、`versionCode` 和商店策略允许回退，并准备数据库迁移和服务端兼容方案。线上发布通常通过分批、暂停或商店版本回退完成；本地 Demo 不会真的操作这些系统。

## 页面 Demo 的边界

页面把四项工作拆成可勾选清单：自动检查、真机回归、发布记录和回滚方案。勾选只改变 Compose 页面状态，用来理解发布流程的完整性，不会上传应用、安装设备、发布商店或执行回滚。

## 发布记录模板

```text
发布日期与环境：
提交版本：
构建变体与任务：
包名 / versionCode / versionName：
签名证书指纹：
APK/AAB 路径与 SHA-256：
自动检查结果：
真机回归设备与结果：
监控指标与告警：
暂停/回滚条件：
负责人和审批人：
```

## 验收清单

1. 进入 Day79，逐项勾选四个发布阶段。
2. 说明自动检查和真机回归解决的问题不同。
3. 能写出包含版本、变体、签名和产物校验值的发布记录。
4. 能说明为什么回滚还需要考虑数据迁移和服务端兼容。
5. 区分本地构建成功、测试通过、已发布和线上稳定。

本课未上传商店、未安装真机、未执行线上发布或回滚；这些属于独立的发布验证环节。
