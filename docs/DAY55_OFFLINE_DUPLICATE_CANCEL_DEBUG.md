# Day55 · 断网、重复消息、取消和调试

## 综合调用链

```text
用户操作
 → 检查当前网络/任务状态
 → 记录 requestId 和阶段（敏感字段脱敏）
 → 可取消的异步任务
 → 在线成功 / 离线 / 取消 / 失败
 → 统一 UI 状态
```

入口：首页 → Day55。源码：[NetworkDebugDemo.kt](../app/src/main/java/com/example/myapplication/day55/NetworkDebugDemo.kt)。本课不读取真实网络状态，不制造真实断网；所有结果可重复。

## 断网不是一种错误

在线状态只是发起前的提示，不能保证请求期间网络不变。真实网络应以 socket/HTTP/WebSocket 的结果为准：可能超时、DNS 失败、连接断开、服务端拒绝或恢复。网络恢复也不等于原请求自动成功。

本例在等待期间切换离线，完成时返回 OFFLINE；恢复后需要用户重新发起。生产重试要考虑请求幂等、退避、用户意图和是否已有服务端处理，不能因为网络断开就无限重放。

## 重复消息与幂等

`event-55` 第一次处理成功，第二次被 `IdempotentProcessor` 忽略。这个集合只属于当前页面内存，不是数据库或服务端保证。真实消息要使用服务端可识别的幂等键、唯一约束或事务；发送按钮禁用只能防止部分 UI 重复，不能防住重连、重试和多设备重复。

对于“支付、完成课程、创建订单”等副作用操作，客户端重复显示一条不代表服务器只执行一次。先明确业务幂等契约，再决定是否重试和如何查询最终状态。

## 取消和失败的区别

- **取消**：页面离开、用户主动取消或上层任务取消；`CancellationException` 应继续传播，不伪装成网络错误。
- **断网/超时**：任务可能失败，也可能服务端已经处理，需要按协议查询或幂等重试。
- **业务拒绝**：网络通了，服务端明确返回错误，不应当作断网。

本例用 `rememberCoroutineScope`，离开组合自动取消。接入真实客户端时还需显式关闭 WebSocket、取消上传、解除监听；协程取消不保证远端没有继续处理。

## 调试日志如何脱敏

保留：`requestId`、阶段、协议号、HTTP 状态、错误类型、耗时、页面实例、变体版本。脱敏：Authorization、Cookie、Token、签名 URL、用户隐私和完整文件内容。

本例展示 `token=<redacted>`，并不把真实凭证放入内存。日志应可关联一次请求，又不能凭日志直接取得会话。Release 日志级别和采集范围应更严格，调试开关不能改变安全边界。

## 取消后为什么仍要过滤回调？

网络库、SDK 或线程池可能有已经排队的回调。使用任务代次、requestId、disposed 标志或连接实例 id，确认回调属于当前页面和当前请求，再更新状态。不能只因为调用了 cancel 就假定所有回调瞬间消失。

## 验收

1. 发起请求期间模拟断网，看到 OFFLINE；恢复网络后重新发起才成功。
2. 发起请求期间点击取消，看到 CANCELLED，不显示网络错误。
3. 连续处理 event-55，第一次成功、第二次忽略。
4. 查看日志，能指出 requestId 和阶段，同时确认没有 Token/Cookie。
5. 能解释网络状态提示、请求结果、取消、幂等和日志脱敏之间的区别。
6. 能把 Day51～55 串起来：统一请求、上传、长连接、消息、断网与调试。
